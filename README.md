# IDBS-ZG Scout Portal
idbs-zg-portal


A web app for **Ismaili District Boy Scouts Group – Zulfiqarabad** to replace paper
enrollment forms. Leaders fill in a digital form (with a camera photo), the
system generates a unique QR-coded Scout ID, and everything is stored in a
free cloud database the admin can manage from one dashboard.

- **Frontend:** React (Vite)
- **Backend / Database:** Supabase (free tier — Postgres database, login system, and photo storage all in one, $0 cost)
- **Hosting:** GitHub Pages / Vercel / Netlify (all free)

---

## 1. How the ID system works

Every scout gets an ID like `IDBS-ZG-BS-0007`:

| Age | Group | Code |
|---|---|---|
| under 12 | Shaheen Scout | `SS` |
| 12 – 17 | Boy Scout | `BS` |
| 18+ | Rover Scout | `RS` |

The number at the end is a running count for that group (auto-generated by
the database, so it can never be duplicated even if two leaders submit at
the same second). A QR code of this ID is generated automatically and shown
on-screen as a printable ID badge.

Each group has **its own table** in the database: `shaheen_scouts`,
`boy_scouts`, `rover_scouts`.

## 2. Set up the backend (Supabase) — free, ~10 minutes

1. Go to **https://supabase.com** → **Start your project** → sign up (free, no credit card).
2. Click **New Project**. Choose any name (e.g. `idbs-zg-portal`), set a
   database password (save it somewhere safe), pick the region closest to
   you, and click **Create new project**. Wait ~2 minutes while it spins up.
3. In the left sidebar, open **SQL Editor** → **New query**.
4. Open `supabase/schema.sql` from this project, copy the **whole file**,
   paste it into the SQL editor, and click **Run**. This creates all 3 scout
   tables, the login/roles table, the ID generator, the activity log, and
   the photo storage bucket.
5. *(Optional, advanced)* If you also want the daily age-check to run
   automatically on Supabase's servers (instead of just whenever the admin
   opens the dashboard, which already works fine on its own), also run
   `supabase/optional_daily_cron.sql`.
6. Go to **Project Settings → API**. Copy the **Project URL** and the
   **anon public key** — you'll need these in step 3 below.

### Create your admin and leader logins

1. In Supabase, go to **Authentication → Users → Add user**. Create a user
   for yourself (the admin) with an email and password. Do the same for
   each leader who needs to log in.
2. Go to **Table Editor → profiles → Insert row** for each user you just
   created:
   - `id`: paste the user's ID (copy it from the Authentication → Users list)
   - `full_name`: their name
   - `role`: `admin` for yourself, `leader` for troop leaders

There is no public sign-up page on purpose — accounts are only created by
you, the admin, through Supabase. This keeps scout data private to your
group.

## 3. Set up the frontend (React)

1. Unzip this project and open a terminal inside the `scout-portal` folder.
2. Install dependencies:
   ```bash
   npm install
   ```
3. Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
   Open `.env` and paste in your Supabase **Project URL** and **anon public
   key** from step 2.6 above.
4. Run it locally to test:
   ```bash
   npm run dev
   ```
   Open the printed `localhost` link, log in with the admin account you
   created, and try submitting a test form.

## 4. Host it for free

You have three good $0 options. **Vercel or Netlify are recommended** —
they're simpler than GitHub Pages for a React app with routing (no extra
config needed).

### Option A — Vercel (recommended, easiest)

1. Push this project to a new GitHub repository (see step 5 below).
2. Go to **https://vercel.com** → sign up with your GitHub account (free).
3. Click **Add New → Project**, select your repository.
4. Vercel auto-detects Vite/React. Before deploying, open **Environment
   Variables** and add:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   (same values from your `.env` file)
5. Click **Deploy**. You'll get a free `https://your-project.vercel.app`
   URL. Every time you push to GitHub, it redeploys automatically.

### Option B — Netlify (also easy, same idea as Vercel)

1. Push to GitHub.
2. Go to **https://netlify.com** → **Add new site → Import an existing
   project** → pick your repo.
3. Build command: `npm run build`, publish directory: `dist`.
4. Under **Site settings → Environment variables**, add
   `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
5. Deploy. You'll get a free `https://your-project.netlify.app` URL.

### Option C — GitHub Pages

1. In `vite.config.js`, change `base: '/'` to `base: '/your-repo-name/'`.
2. Since GitHub Pages can't hold secret environment variables safely for a
   public repo, and Supabase's anon key is safe to expose publicly (it only
   works within the permissions you set with Row Level Security, which the
   schema already locks down), you can hardcode the values directly in
   `src/supabaseClient.js` instead of using `.env` for this option, **or**
   set repository secrets and inject them at build time via a GitHub Actions
   workflow (more advanced — ask if you'd like this workflow file added).
3. Push your project to GitHub, then run:
   ```bash
   npm install
   npm run deploy
   ```
   This uses the `gh-pages` package (already in `package.json`) to publish
   the `dist` folder to a `gh-pages` branch.
4. In your GitHub repo, go to **Settings → Pages** and set the source to
   the `gh-pages` branch. Your site will be live at
   `https://<your-username>.github.io/<repo-name>/`.

## 6. How the key features work

- **QR ID cards** — generated client-side with the `qrcode.react` library
  the moment a form is saved (Admin → Scout → *Print ID Card* also works).
- **Camera photo capture** — uses the device camera directly through the
  browser (`getUserMedia`); falls back to a normal file picker if camera
  access is denied.
- **Custom alerts/popups** — no browser `alert()`/`confirm()` anywhere in
  this app. All notifications are styled toast popups
  (`src/context/AlertContext.jsx`) and all confirmations are custom modal
  dialogs (`src/components/ConfirmModal.jsx`).
- **Revert / correction workflow** — the admin can send any active form
  back to the leader who submitted it (with a reason). It shows up under
  that leader's **Reverted Forms** page until they fix and resubmit it.
- **Promotions** — every time the admin dashboard loads (once per day per
  browser, or on demand via *"Re-check ages now"*), the app compares each
  active scout's date of birth against today's date. Anyone who has aged
  into a new group (e.g. turned 12) is flagged and shown in a popup. As
  requested, the system **never moves the record automatically** — the
  admin clicks *"Revert for promotion"*, which sends it to the leader, who
  re-enters the scout's details into the new group manually, generating a
  brand-new Scout ID in the new table.
- **Admin dashboard** — total/active/reverted/promotion-due counts, a
  searchable table per group, and full record + printable badge view for
  every scout.

## 8. Costs

Everything here runs entirely on free tiers:

- **Supabase free tier:** 500MB database, 1GB file storage, 50,000 monthly
  active users — more than enough for a scout troop.
- **Vercel/Netlify/GitHub Pages free tier:** unlimited personal projects
  with generous bandwidth for a low-traffic internal tool like this.

If your group ever grows well beyond these limits, both Supabase and the
hosting providers offer paid upgrade tiers, but you shouldn't need one for
this use case.
